# Runtime Catalog — the prepared JSON catalog consumers read

> **Brought home 2026-09-23** (Phase01 step 1.3) from the IMRSV platform docs. **This repo is now the authority** for this spec; consumers point here.

The **runtime catalog** is the machine-side projection of the authored [manifest](Manifest.md) lockfile: a single JSON file, deterministically generated from the YAML lockfile + the materials tree, that consumers read to list and resolve articles **instead of scanning the filesystem**. The authored YAML lockfile stays the source of truth; the runtime catalog is a derived, committed artifact.

> **Ownership boundary.** **Matter Library** owns curation/release authoring (the `*.lock.yaml`). The **projector** (`tools/converters/project_runtime_catalog.py`) owns validation + projection (YAML → JSON). **Consumers** read a prepared runtime contract (this JSON) — they need a JSON reader only, no YAML parser. The two schemas are separately owned: [Manifest.md](Manifest.md) is the authored source; this doc is the runtime projection.

## Artifact

- **Filename:** `matterlib-<release>.catalog.json` (sits beside the authored `matterlib-<release>.lock.yaml`, e.g. `library/releases/matterlib-0.1.0.catalog.json`). *(Updated 2026-09-23, measured: `library/releases/` holds `matterlib-0.0.1.catalog.json` and `matterlib-0.1.0.catalog.json`, each beside its lockfile.)*
- **Generated by:** `tools/converters/project_runtime_catalog.py` (validates the lockfile, then projects). Deterministic — sorted material order + sorted keys, so a re-run is byte-identical (the catalog-freshness/determinism lane in `tools/validators/run_all.py`).
- **Co-located runtime form:** at runtime the catalog file sits at the root of a directory whose sibling `materials/` subtree holds the payloads; `payload_path` is resolved relative to the catalog file. The versioned install layout is the [install root](../Distribution/ReleaseModel.md).

## Schema

```json
{
  "materials": [
    {
      "creator_selectable": true,
      "display_name": "ABS_Matte_Clean_Base",
      "domain": "synthetic",
      "id": "synthetic/plastic/ABS_Matte_Clean_Base_s01",
      "material_class": "plastic",
      "payload_path": "materials/synthetic/plastic/ABS_Matte_Clean_Base_s01_v01.mtlx",
      "scale": "s01",
      "status": "approved",
      "version": "v01"
    }
  ],
  "release": "0.1.0",
  "schema_version": 2
}
```

*(Updated 2026-09-23, measured: this entry is copied from `library/releases/matterlib-0.1.0.catalog.json`, whose top-level keys are exactly `materials`, `release`, `schema_version` (= 2) and whose entries carry exactly the nine fields in the table below, keys sorted; the former example showed the `0.0.1` pilot with `status: draft`.)*

| Field | Type | Meaning | Source |
|-------|------|---------|--------|
| `schema_version` | int | Runtime-catalog data-contract version (this doc). Bumped on a breaking JSON-shape change — **independent** of the library `release` semver. Bumped `1 → 2` for the additive `creator_selectable` field. | this doc |
| `release` | string (semver) | The library release this catalog projects. | lockfile `release` |
| `materials[]` | array | One entry per material, ordered deterministically (by `id`). | lockfile `materials[]` |
| `materials[].id` | string | The qualified Matter identity — Domain/Class folder path + the [qualified name](../Ontology/Identity.md) **including** the `sNN` scale tag. The resolution key (no alias layer). | lockfile `id` |
| `materials[].display_name` | string | Short display label `Material_Variant_Condition_Detail` (the qualified leaf name with the `sNN` tag dropped). UI/display metadata derived from `id`, never a resolution key. | derived from `id` |
| `materials[].domain` | string | The Domain segment of `id` (`natural`, `engineered`, …). | derived from `id` |
| `materials[].material_class` | string | The Class segment of `id` (`stone`, `metal`, `plastic`, …). A consumer's picker filter key is this field ([Glossary](../../Glossary.md) §Material `category`). | derived from `id` |
| `materials[].scale` | string | The `sNN` scale tag off the qualified name (empty for an off-grammar system material with no scale tag). | derived from `id` |
| `materials[].version` | string (`vNN`) | The material's own version axis (never conflated with `release`). | lockfile `version` |
| `materials[].status` | string | Lifecycle status (`draft`/`candidate`/`approved`/`deprecated`/`retired`). | lockfile `status` |
| `materials[].creator_selectable` | bool | Whether the material appears in the Creator-facing browse/assign set. **Default `true`; `false` only on the system material `IMRSV_MissingMaterial`.** Honored by the [Blender Asset-Browser library](../../Glossary.md) generator (`tools/generators/gen_asset_library.py` excludes non-selectable articles from the generated set) and by consumers' browse lists. It is a **browse filter only** — exact system lookup by identity still resolves `IMRSV_MissingMaterial` for the broken-material fallback. | lockfile / derived (default `true`) |
| `materials[].payload_path` | string | Path to the `.mtlx` payload, **relative to the catalog file** (`materials/<id>_<version>.mtlx`; bare `materials/<id>.mtlx` for the off-grammar system material). | derived from `id` + `version` |

*Consumer-side (IMRSV): how the catalog's `material_class` replaced the old shader-family `category` in IMRSV's read surface and picker — see [Consumers](../Consumers.md).*

### Planned: the per-article master token *(planned)*

> **Drift (2026-09-23):** the catalog carries **no per-article [master token](../../Glossary.md)** today (measured: no `master` key in either live catalog or lockfile), so consumers still route articles to masters by class rules held in their own code; R14 publishes the master contract as data, which adds the token to the lockfile and this catalog under a future `schema_version` bump — owned by the release-bundle / consumer-contract phase (R14).

### Off-grammar system material

`IMRSV_MissingMaterial` (`utility/virtual/IMRSV_MissingMaterial`) has no `sNN` scale tag and resolves by bare `<id>.mtlx` (no `_vNN` axis in the filename), carrying a nominal `version: v01`. Its `scale` is empty and its `payload_path` omits the `_<version>` suffix. It is also the sole material carrying `creator_selectable: false` — so it is never offered in the Creator browse/assign set while still resolving by exact identity for the broken-material fallback. See [Manifest.md](Manifest.md) §Off-grammar exception. *(Updated 2026-09-23, measured: in `matterlib-0.1.0.catalog.json` its `scale` is `""`, `payload_path` is `materials/utility/virtual/IMRSV_MissingMaterial.mtlx`, and it is the only `creator_selectable: false` entry.)*

### What the runtime catalog does NOT carry

Per-material **parameter definitions** (`default_parameters`, the LCD parameter set) stay out of the runtime catalog — a consumer parses the resolved `.mtlx` on demand (the runtime catalog maps identity → payload path; the parameter detail comes from parsing that file). This keeps the catalog lean and avoids duplicating `.mtlx` content. *(Revisit only if a parse-free parameter lookup is ever needed — then the catalog grows parameter data; not v1.)* Provenance, licence and evidence never reach the catalog either ([Manifest.md](Manifest.md) §provenance).

## Status

**The runtime contract.** Consumers read this catalog; there is no directory-scan read path. Versioned by its own `schema_version` (currently `2`); the catalog seam is additive JSON.

## History

- Pre-standalone (2026-06 → 2026-07): consumers switched from scanning the materials directory to reading this catalog in one hard cutover, with no dual-read period.
- Pre-standalone: the catalog's `category` meaning shifted from shader family to Matter Class once the library went OpenPBR-only, which is why the catalog carries `material_class` and no shader-family field.
- 2026-07-17: `creator_selectable` was added and `schema_version` bumped `1 → 2`.
