# Site File — what the library's website reads about each article

> **⚠ DRAFT (2026-10-14, Phase13 13.1).** Only the website's staging reads this file, so its shape may still change at little cost, and the change is told to the site's builders in [PlatformDependencies](../../Planning/PlatformDependencies.md) M9. It stops being a draft with the library's first versionable release (research `261014_R_RoadmapOrder.md` F-RO-26). **This repo owns the shape** (RD-WS-4); the site adopts it.

The **site file** is the presentation layer of a release (`261014_R_MaterialPipeline.md` F-MP-13): everything the library's website shows about each article, projected from the article's own records (its recipe, its `.mtlx`, the pilot lockfile's provenance, and the parity rig's scorecard). The [runtime catalog](RuntimeCatalog.md) stays the engines' lean file and is unchanged, and `no_projection_guard` still holds for it. The website is a consumer like any other ([Consumers](../Consumers.md) §The library's website): it reads this file and the release beside it, never this repo.

## Artifact

- **Filename:** `matterlib-<release>.site.json`, published as an asset of the GitHub release (or **dev snapshot**) it describes, beside its pictures, one zip per article and `SHA256SUMS`. A dev snapshot's `<release>` is `X.Y.Z-dev.N` ([NamingConventions](../../NamingConventions.md) §Identifier vocabularies).
- **Generated by:** `tools/releases/build_snapshot.py`, into a git-ignored `library/snapshots/<tag>/`. **Never committed**, and never written to `library/releases/`, whose files the release gates read.
- **Digests:** `SHA256SUMS` (`sha256sum -c` form) covers every asset, this file included. Each picture and zip also carries its own `sha256` here.

## The rule: an absent field means "not known yet"

**A field the library does not hold yet is left out, never filled with a default or a made-up value.** A reader shows the gap honestly: the site draws a labelled swatch where there is no picture, derives nothing it cannot show as derived, and shows no summary where there is none. *(Working Agreement, No Mock Data Masquerading as Real; F-RO-26.)*

## Schema

```json
{
  "schema_version": 1,
  "release": "0.2.0-dev.1",
  "made": "2026-10-14",
  "draft": true,
  "materials": [ { "id": "engineered/metal/Copper_Verdigris_Aged_Base_s01", "…": "…" } ]
}
```

| Field | Type | Meaning | Source |
|---|---|---|---|
| `schema_version` | int | This file's contract version, independent of the release and of the runtime catalog's. | this doc |
| `release` | string | The release or snapshot this file describes (`matterlib-` is not repeated). | the tag |
| `made` | date | The day it was built. | the builder |
| `draft` | bool | `true` while this spec is a draft. | this doc |
| `materials[]` | array | Every article the release lists, sorted by `id`. A dev snapshot lists every article on disk, each with its `status`, the same set as the dev catalog. | — |

**Per material — identity** (as the [runtime catalog](RuntimeCatalog.md)):

| Field | Meaning |
|---|---|
| `id`, `version`, `display_name`, `domain`, `material_class`, `scale`, `status`, `creator_selectable` | As the runtime catalog defines them. `creator_selectable: false` only on `IMRSV_MissingMaterial`; a site lists it or not as its browse rule says. |
| `identity` | The qualified name with its version (`Copper_Verdigris_Aged_Base_s01_v01`), the stem every file name below begins with. |
| `label` | The name a person reads. **Derived** from the tokens (PascalCase split, the default tokens `Natural`, `Clean` and `Base` dropped, sentence case, acronyms and roman numerals kept): `Copper verdigris aged`. Where that reads badly, the recipe's `label` replaces it (Phase13 13.2). |
| `master` | The article's master token ([MasterSet](../Ontology/MasterSet.md)). |
| `meters_per_tile` | The real-world size of one texture tile, from the article's metadata. |

**Per material — what a Creator may change:**

| Field | Meaning |
|---|---|
| `controls[]` | Each Creator port the article declares ([LCDSchema](LCDSchema.md)): `port`, `name` (its UI name), `type`, `start` (the article's own value: a number, or a list per channel) and `range` (`min`, `max`, `null` where open; `min_exclusive: true` where the minimum is not allowed, `uv_scale`). Ranges are LCDSchema's frozen ones, per channel. |
| `wear_layers[]` | Each wear layer: `layer` (its name, e.g. `Dust01`), the `density_port` that turns it up and, for a deposit, its `color_port`. Absent on an article with none. |

**Per material — where it came from** (the compliance layer, as far as the library holds it):

| Field | Meaning |
|---|---|
| `licence` | `CC0-1.0`, every article (RD-RO-2). |
| `sources[]` | The recipe's sources: `kind` (`ambientcg`, `physicallybased`, `procedural`, `judgement`) with what that kind records (an `asset` and `url`, the values used, a `why`). For a pilot article whose recipe has none, its textures' lockfile provenance (`kind`, `license`, `url`), wear layers excepted: like a recipe's, these sources are the article's own, and its wear layers are under `wear_layers`. Absent when nothing is recorded. |
| `contributor` *(planned)* | A contributor's handle, when one was given: credit as a courtesy and for the platform's Forseti tracking, never a licence condition (RD-RO-2). Nothing records one yet. |
| `origin` | Where the article came from, any of: `scan` (a scanned source, e.g. ambientCG), `procedural` (a generator), `measured` (measured values, e.g. Physically Based), `agent-drafted` (an agent wrote the recipe). Derived from its sources at 13.2, kept in the recipe, confirmed by the maintainer (F-MP-18). Absent until written. |

**Per material — evidence and pictures:**

| Field | Meaning |
|---|---|
| `parity` | Present when the parity rig has rendered the article. `tools` (which of `storm`, `blender`, `unreal` ran), `scene` (the rig's test scene), `measured` (the date of the rig's scorecard, absent if it has none) and `controls` (per port: `verdict`, the worst of its rows, and `rows[]` each with its `setting` and `verdict`). The words are the rig's own Moved verdicts: `moved alike` · `UNEVEN` · `ONE-SIDED` · `no change in any tool` ([_Architecture](../_Architecture.md) §LCD). **A control with no entry was not swept**, which is not a pass. **Evidence is published as measured:** a picture or verdict older than the current masters or Unreal runtime says so only through its date (Phase13 Q-P13-4). |
| `pictures[]` | `role` (`rig` today; `thumbnail` once [Catalog](../Catalog/Catalog.md) §Thumbnails exist), `tool`, `view` (`wide` or `close`), `file` and `sha256`. **Only the test scene's default pictures** are published: never a character render, a sweep picture, or a rig log or job file. WebP, at the rig's 512 px. |
| `download` | `file` (`<identity>.zip`), `bytes`, `sha256` and `textures` (how many). The zip holds `<identity>.mtlx` with every texture reference rewritten to `textures/<name>`, and those textures, shared wear layers included, so it opens anywhere with no search path. **Fit-set pictures** (hair cards, eyes) are supplied when an article is bound to a mesh, never referenced by it, so they are not in the zip. |
| `summary`, `search_words` | A one-line public description and the words a search should find it by, written by the agent and confirmed by the maintainer with the picture (F-MP-14). |

## Limits

GitHub allows up to 1000 assets a release, each under 2 GiB. A dev snapshot publishes at most seven per article (six pictures and a zip), which fits about 140 articles; the builder fails rather than drop an asset past the limit. Splitting belongs to the release-bundle phase (F-MP-30).
